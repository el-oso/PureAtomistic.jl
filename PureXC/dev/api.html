PureXC.xc_derivatives Function
julia
xc_derivatives(f, Val(k), ρ)
xc_derivatives(f, Val(k), ρ, σ)

The energy per volume e of the functional f and all its partial derivatives up to order k, as a NamedTuple. A restricted input is a number ρ (and σ for a GGA); a polarized input is ρ = (ρα, ρβ) (and σ = (σαα, σαβ, σββ)). Order j ≥ 1 has one field per split a + b = j with a descending, named v[j]rho[a]sigma[b] with exponents shown above 1 (vrho, v2rhosigma, v3rho2sigma). Restricted fields are numbers. Polarized fields are tuples over the density multisets of size a in lexicographic order over (α, β), each followed by the σ multisets of size b in lexicographic order over (αα, αβ, ββ). The result type is the promotion of the functional's number type and the input types. Invalid inputs throw an ArgumentError.

PureXC.xc_evaluate! Function
julia
xc_evaluate!(out, f, Val(k), ρ)
xc_evaluate!(out, f, Val(k), ρ, σ)

Write the energy per volume of the functional f and its derivatives to order k (xc_derivatives) at every point of the arrays ρ (and σ) into the arrays of the NamedTuple out, which has exactly the fields of xc_derivatives. Restricted inputs are vectors; polarized inputs are a 2 × n matrix ρ and a 3 × n matrix σ with the spin on dimension 1. Each output field is a matrix with one row per component of the field (see xc_derivatives; one row for a scalar field) and the point axis of the inputs as its columns. All inputs are validated before the first output is written; an invalid input throws the ArgumentError of xc_derivatives, and mismatched axes throw a DimensionMismatch.

Every view, at any level between an input or output and its root, must lie in bounds of its parent: a view whose indices fail checkbounds(Bool, parent, indices...) (one made by Base.unsafe_view) makes xc_evaluate! throw ArgumentError("xc: an array view lies outside its parent") before writing anything.

No output may share memory with an input or with another output: if one does, xc_evaluate! throws ArgumentError("xc: an output shares memory with an input or another output") before writing anything. The same error is thrown for an output that overlaps itself: a view, at any level between the output and its root, whose indices repeat a value (a repeated vector index, a range of step zero), or a root that defines strides with a stride of zero in a dimension of length greater than one, so that two points may write one address.

Every argument is resolved through parent to its root array: the array that is its own parent, or the last AbstractArray of the chain when a parent returns something that is not an AbstractArray. When both roots have a known address range (an Array or Memory of a bits type, or a root of a bits type that defines strides and whose pointer returns a Ptr), arrays whose roots occupy disjoint address ranges are accepted, and arrays over one storage are accepted only when the test is exact: Arrays and views of an Array indexed by integers and ranges whose address spans are disjoint, or views of the same Array whose integer or range indices are in bounds and select disjoint sets in some dimension (an Array stores each index at its own address), so disjoint rows or column blocks of one matrix are accepted. Any other array over the same storage is rejected, even when its elements are disjoint: a reshape, transpose, OffsetArray or other wrapper of one part of a buffer against another part, and views of one Array that differ only in vector or logical indices. When either root has no known address range, the two roots share memory when their Base.dataids have a value in common. An array type that holds memory it does not expose through parent, pointer and strides must therefore define parent returning an AbstractArray over that memory, or Base.dataids: without either (a parent that returns something other than an AbstractArray counts as none), its dataids is its own objectid, and an overlap with its memory goes undetected. Two arrays over the same file mapped twice, at two addresses, cannot be detected.

PureXC.XC Type
julia
XC(terms)

The functional Σ wᵢ·fᵢ over terms = ((w₁, f₁), (w₂, f₂), …), with real weights wᵢ. All terms belong to one family (LDA or GGA). energy_density, xc_derivatives and xc_evaluate! sum the weighted terms. Each term is evaluated by its own driver in its own evaluation type (_evaluation_type), or in Float64 when the XC is Float32 above its _float32_max_order; the weighted terms are summed in the widest of those types, and each output is rounded once to the result type. A term may itself be an XC: it is evaluated as its weighted sum, in the evaluation type of the outer XC, and rounded with the outer sum.

PureXC.PW92Correlation Type
julia

Perdew–Wang 1992 correlation in the number type T. params holds the three parameter sets of the fit G, for ε_c(r_s, 0), ε_c(r_s, 1) and −α_c(r_s) in that order, each as (A, α₁, β₁, β₂, β₃, β₄) with the exponent p = 1. fz20 is f''(0) and thresholds gives the density threshold and the spin-polarization threshold. Thresholds ​

PureXC.Thresholds Type
julia
Thresholds{T}(density, sigma, zeta)

The thresholds of a functional's PureXC rule, in its number type T: the density threshold density, the reported gradient threshold sigma and the spin-polarization threshold zeta. The floor applied to a σ is sigma_floor, which is sigma^2, or floatmin(Float32) where that is larger in the thresholds default_thresholds builds for Float32.

source
PureXC.default_thresholds Function
julia
default_thresholds(T, density, sigma, zeta)

The thresholds of a functional built for the number type T, from the spec values density, sigma and zeta. Each value is converted to T. For Float32, zeta is eps(Float32) and a density or σ floor below floatmin(Float32) is raised to floatmin(Float32).
