Molden files ​

QuantumEngine.IO.MoldenShell Type
julia
MoldenShell{T}(atom, l, exponents, coefficients)
MoldenShell(atom, l, exponents, coefficients)

A contracted Gaussian shell of a Molden file: the index atom of the atom it sits on (in the atom list of its MoldenData), its angular momentum l (0 to 4: s, p, d, f, g), and the exponents and contraction coefficients of its primitives, one of each per primitive. The coefficients are stored as given; their normalization is the caller's. Without a type parameter, T is the floating-point type of the two vectors. Throws an ArgumentError for an l outside 0:4, an atom below 1, no primitive, vectors of different lengths, offset vectors, an exponent that is not finite and positive, and a coefficient that is not finite.

source
QuantumEngine.IO.MoldenOrbitals Type
julia
MoldenOrbitals{T}(energies, occupations, coefficients)
MoldenOrbitals(energies, occupations, coefficients)

The molecular orbitals of one spin: their energies (hartree), occupations, and the coefficients matrix, n_ao × n_mo, whose column j holds orbital j over the atomic orbitals in the order of the shells. Without a type parameter, T is the floating-point type of the three arrays. Throws an ArgumentError for offset arrays, sizes that disagree, and a value that is not finite.

source
QuantumEngine.IO.MoldenData Type
julia
MoldenData{T}(title, atoms, shells, alpha, beta)
MoldenData(title, atoms, shells, alpha, beta = nothing)

The contents of a Molden file: a one-line title, the atoms (positions in bohr), the basis shells, ordered by atom, the alpha orbitals and the beta orbitals (nothing for a restricted wave function). The coefficient matrices have one row per Cartesian atomic orbital of the shells, (l + 1)(l + 2)/2 per shell. Throws an ArgumentError for a title with a line break, with leading or trailing whitespace or starting with [, none of which a Molden file can hold; an offset vector; no atoms; an atom with a non-finite position; a shell on an atom that does not exist; shells out of atom order; no alpha orbitals; and a coefficient matrix whose row count is not the number of atomic orbitals. (read_molden rejects a file with no atoms or no alpha orbitals.)

source
QuantumEngine.IO.write_molden Function
julia
write_molden(io::Base.IO, d::MoldenData)

Writes d as a Molden file: [Molden Format]; [Title] and the title line; [Atoms] AU with one line <symbol> <index> <Z> <x> <y> <z> per atom, in bohr; [GTO] with, per atom, the line <atom> 0, then per shell <s|p|d|f|g> <nprim> 1.00 and one <exponent> <coefficient> line per primitive, then a blank line; and [MO] with, per orbital, alpha before beta, the lines Sym= A, Ene= <energy>, Spin= Alpha or Spin= Beta, Occup= <occupation> and one <ao> <coefficient> line per atomic orbital. Every number is written as the shortest decimal that reads back as the same Float64 (string(::Float64)), so read_molden reads back the values written. The coefficients are written as given. Atomic masses are not written, since a Molden file has no field for them; read_molden gives each atom its default mass.

There is no [5D] line, so a reader takes every shell as Cartesian. Within a shell the atomic orbitals are expected in the order of the Molden format:

  • d: xx, yy, zz, xy, xz, yz;

  • f: xxx, yyy, zzz, xyy, xxy, xxz, xzz, yzz, yyz, xyz;

  • g: xxxx, yyyy, zzzz, xxxy, xxxz, yyyx, yyyz, zzzx, zzzy, xxyy, xxzz, yyzz, xxyz, yyxz, zzxy.

source
QuantumEngine.IO.read_molden Function
julia
read_molden(io::Base.IO; source = "<stream>") -> MoldenData{Float64}

The Molden file in io. It starts with [Molden Format]; then come the sections [Title] (optional), [Atoms], [GTO] and [MO], in that order, each at most once. Section names and keywords are matched without regard to case.

  • The [Atoms] unit is AU, (AU) or Bohr (bohr), or Angs, Angstrom or (Angstrom) (Å, converted to bohr). Each atom line is <symbol> <index> <Z> <x> <y> <z>, with the indices 1, 2, … in order and Z the atomic number of the symbol (0 for a ghost). Each atom has the mass Atom gives it by default.

  • In [GTO], an atom block starts with <atom> 0 and holds shells <label> <nprim> [1.00], each followed by its <exponent> <coefficient> lines; the labels are s, p, d, f and g, and the scale factor, when given, is 1.

  • In [MO], each orbital has the keyword lines Ene= and Occup=, and optionally Sym= (read and dropped) and Spin= (Alpha or Beta; Alpha when absent), followed by <ao> <coefficient> lines with increasing indices; an atomic orbital without a line has coefficient 0. Every shell is read as Cartesian.

Numbers may use a Fortran D exponent (1.0D-03). Errors are InputErrors naming source and the line; among them, an unknown section, such as [5D], and a number that is not finite.

QuantumEngine.Input.InputFile Type
julia
InputFile(; kwargs...)

Every setting of an input file, each keyword argument a field with the oracle's default. Atom positions are in bohr, and every atom index (constraints, fragments, the ONIOM model atoms) is 1-based. lattice holds the cell vectors as rows, in Å whatever the geometry unit; freeze_bond targets are in bohr and angle targets in radians. basis holds the basis-set name in lowercase; alias resolution belongs to the basis-set reader. dos_sigma is in eV.

QuantumEngine.Input.method_word Function
julia
method_word(tokens::AbstractVector{<:AbstractString}) -> Union{Nothing,MethodSpec}

The method that the tokens after the method keyword name, or nothing when they name none. The first token is the method word, in any ASCII case (accepted_methods()); rhf, rmp2, rmp2-f12, rccsd and rccsd-f12 ask for a restricted reference, uhf, ump2, uccsd and uccsd(t) for an unrestricted one, and every other word for AutoReference. casscf(e,o) is one token. libxc_gga x c and libxc_mgga x c read the two following tokens as Libxc IDs, and libxc_hgga id exx and libxc_hmgga id exx read an ID and the exact-exchange fraction; a missing or malformed number gives nothing. Tokens after those the method reads are left to the caller. tokens may have any indices.

QuantumEngine

Its submodules are Errors (the error types), Units (physical constants and the element table), System (atoms, molecules, electron counts and the nuclear repulsion), IO (the xyz, PDB, CIF and Molden files, the logger and the number formats) and Input (the typed input file, the words of its keywords, the .inp parser and the JSON and dictionary readers; YAML files are read through the extension QuantumEngineYAMLExt).

QuantumEngine.Errors Module
julia
QuantumEngine.Errors

The error types of QuantumEngine and the record of a lenient-mode warning. Each showerror method prints the message after a prefix that names its kind (input:, basis:, scf:, …). Messages are stored as LazyString, so an interpolated lazy"..." message is not rendered until it is shown.

QuantumEngine.IO Module
julia
QuantumEngine.IO

Molecule files and output. The xyz reader (every frame) and writer, and the PDB and CIF readers: each reader reads in strict mode by default, where every input the oracle accepts silently but that is not valid is an InputError, or in lenient mode, where it takes the oracle's value and records an InputWarning. Positions are in bohr; the files hold Å. The Logger, which writes each line to standard output and to the log file, the oracle's fixed output lines, and the Rust-compatible number formats they are built from. The Molden data types, with their writer and reader.

source
QuantumEngine.Input Module
julia
QuantumEngine.Input

The typed input file. InputFile holds every setting with the oracle's default, ParsedInput pairs it with the warnings of lenient reading, and the enumerations and structs of its fields name the methods, run modes and options. The vocabulary functions (method_word, run_mode_word, solvent_word and the others) map the words an input file may use to those values, without regard to ASCII case, and return nothing for an unknown word; each has an accepted_* companion that lists its words. parse_inp reads an .inp file into a ParsedInput, and molecule builds the Molecule of an InputFile. Structured input is a tree of Nodes: json_node reads JSON text into one and node any AbstractDict, parse_structured reads the tree into a ParsedInput, and parse_json and parse_dict do both. parse_yaml reads YAML text; its method is in the extension QuantumEngineYAMLExt, which loads with YAML.jl. parse_input reads a file with the reader its extension names (input_format), a molecule file into an InputFile that holds only its atoms.

QuantumEngine.System.Atom Type
julia
Atom{T<:Real}

An atom: its atomic number Z (0 for a ghost), the symbol as written, its position in bohr, whether it is a ghost (it carries basis functions but no nucleus and no electrons) and its mass in amu (0 for a ghost).

julia
Atom(symbol::AbstractString, position::AbstractVector; mass = nothing)

builds an atom with T = float(eltype(position)) from a position of length 3. The symbol is matched without regard to case: El is an atom of element El, and El@, BqEl and Bq-El are ghosts of El. The default mass is that of the most abundant isotope. Throws an ArgumentError for a position whose length is not 3, a bare Bq, a symbol that names no element, a mass given for a ghost, and a mass that is not finite and positive.

QuantumEngine.System.nuclear_repulsion Function
julia
nuclear_repulsion(mol::Molecule{T}) -> T

The repulsion energy Σ_{i<j} Z_i Z_j / r_ij (hartree) of the atoms with Z > 0; ghosts carry no nucleus. Throws an ArgumentError when two such atoms coincide, naming their indices in eachindex(mol.atoms). QuantumEngine.IO.XYZFrame Type
julia
XYZFrame

One frame of an xyz file: its atoms (positions in bohr) and the comment of its second line, with the surrounding whitespace stripped.

source
QuantumEngine.IO.read_xyz Function
julia
read_xyz(io::Base.IO; source = "<stream>", lenient = false, warnings = InputWarning[]) -> Vector{XYZFrame}

Every frame of the xyz text in io. A frame is a line with the atom count, a comment line (line 2 of the frame, even when blank), and one symbol x y z line per atom with the coordinates in Å, which are converted to bohr; columns after the fourth are ignored. Blank lines between the atom lines and between frames are skipped.

Errors are InputErrors naming source and the line. In lenient mode (lenient = true) a frame with fewer atom lines than its count, an unknown element symbol and a non-finite coordinate are read as the oracle reads them, and an InputWarning is pushed onto warnings for each.

Lenient mode does not reproduce the oracle for a frame with more atom lines than its count: the oracle reads one frame and ignores the lines after it, while this reader reads the next line as the count of the next frame, an error in both modes when it is not one.

source
QuantumEngine.IO.write_xyz Function
julia
write_xyz(io::Base.IO, atoms::AbstractVector{<:Atom}; comment::AbstractString = "")

Writes one xyz frame: the atom count, the comment line, and <symbol> <x> <y> <z> per atom with the coordinates in Å, each the shortest decimal that reads back as the same Float64, separated by single spaces. Throws an ArgumentError for a comment with a line break or with leading or trailing whitespace, neither of which read_xyz reads back.

source
QuantumEngine.IO.read_pdb Function
julia
read_pdb(io::Base.IO; source = "<stream>", lenient = false, warnings = InputWarning[]) -> Vector{Atom{Float64}}

The atoms of the ATOM and HETATM records of the PDB text in io; other records are ignored. The coordinates are the Å fields of columns 31–38, 39–46 and 47–54, converted to bohr, and the element is read from columns 77–78, right- or left-justified.

Errors are InputErrors naming source and the line; a file without a record is an error. In lenient mode (lenient = true) a record shorter than 54 columns is skipped; a record without an element in columns 77–78 takes the first character of its atom name (columns 13–16) when it is shorter than 78 columns, and the empty symbol with Z = 1 when it is 78 columns or longer with those columns blank; an unknown element symbol is read as Z = 1, and a non-finite coordinate is kept. These are the oracle's values, and an InputWarning is pushed onto warnings for each.

source
QuantumEngine.IO.read_cif Function
julia
read_cif(io::Base.IO; source = "<stream>", lenient = false, warnings = InputWarning[]) -> Vector{Atom{Float64}}

The atoms of the _atom_site loop of the CIF text in io: a loop_ whose tags include _atom_site_type_symbol and _atom_site_Cartn_x, _y and _z (in Å, converted to bohr), with one whitespace-separated row per atom. Tags are matched without regard to case, and the characters of the type symbol that are not letters are dropped (Fe2+ is iron). Other loops, tag lines outside a loop, and # comment lines are ignored; a tag line after a loop's rows, a new loop_ or a data_ line ends the loop.

Errors are InputErrors naming source and the line. A loop with fractional coordinates and no Cartesian ones throws "cif: only Cartesian _atom_site coordinates are supported", and a file without an atom is an error. In lenient mode (lenient = true) an _atom_site loop with coordinate tags but without the type symbol or one of the Cartesian coordinates is skipped, a row whose value count differs from the tag count is skipped, a coordinate that is not a number reads as 0.0, a non-finite coordinate is kept, and an unknown element symbol is read as Z = 1, as the oracle reads them, and an InputWarning is pushed onto warnings for each.

QuantumEngine.IO.input_line Function
julia
input_line(raw::AbstractString, n::Int) -> (line, tokens)

Line n of an input file, cleaned: a leading UTF-8 byte-order mark removed when n == 1, a trailing \r removed and the surrounding whitespace stripped. tokens are the pieces of line between spaces and tabs. Both are SubString{String}s. Every reader and parser cleans its lines here, so CRLF files, a byte-order mark and tab separators read as the LF, space-separated file.

The one choice between strict and lenient reading. Strict (lenient == false) throws InputError(source, line, msg). Lenient pushes InputWarning(source, line, case, msg) onto warnings and returns, and the caller then takes the value the oracle takes.

QuantumEngine.IO.parse_coordinate Function
julia
parse_coordinate(t::AbstractString) -> Union{Nothing,Float64}

The value of the number token t as Rust's str::parse::<f64>, which the oracle uses, reads it, or nothing for a token it rejects. A decimal beyond the Float64 range reads as ±Inf and one below half the smallest subnormal as ±0.0, where tryparse(Float64, t) returns nothing for both; a hexadecimal float, which tryparse reads and Rust rejects, is rejected. The xyz, PDB, CIF and Molden readers and the .inp parser read their numbers with it.

Number formats ​

QuantumEngine.IO.fmt_fixed Function
julia
fmt_fixed(x::Real, width::Int, prec::Int) -> String

x with prec digits after the decimal point, right-aligned in width characters, as Rust's {:width.prec}: fmt_fixed(-76.301896228438, 20, 12) == " -76.301896228438". Throws an ArgumentError for a prec not in FORMAT_PRECISIONS (0 to 8, 10, 12 and 15).

The digits come from Printf's %.<prec>f, which rounds the exact binary value. Where that value is an exact decimal tie, both Printf and Rust round to even on the ties the item "Rust fixed, integer and string formats" pins; other ties are not checked, and Rust may round them the other way. The parity harness compares parsed numbers, not text, so such a difference is cosmetic.

source

Throws an ArgumentError for a prec not in FORMAT_PRECISIONS. Decimal ties round as in fmt_fixed.
