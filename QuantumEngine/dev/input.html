Input files ​

parse_input(path; lenient) reads an input file with the reader its extension names: .xyz, .pdb and .cif are molecule files, read into an InputFile holding only their atoms; .json goes to parse_json, .yaml and .yml to parse_yaml (with YAML.jl loaded); any other extension is the .inp format. An xyz file given as an input must hold one frame (lenient reading takes the first of several, with an :xyz_frames warning) and at least one atom (lenient reading keeps a frame of none, with an :xyz_no_atoms warning). A path that names a directory is an InputError (io: the path is a directory) whatever its extension. A path that ends in a separator (d.xyz/) has no extension, so it is dispatched as .inp, which rejects it as a directory when it is one; the oracle dispatches it as xyz.

QuantumEngine.Input.parse_input Function
julia
parse_input(path::AbstractString; lenient::Bool = false) -> ParsedInput

The input file path, read by the reader of its input_format, with path as the source of its errors and warnings: parse_inp, parse_json, or parse_yaml, which needs YAML.jl loaded (an InputError in both modes without it). A molecule file (xyz, PDB or CIF) gives an InputFile holding its atoms and every other field at its default, as the oracle reads it; the checks of the other formats (that the input has atoms, and that its charge and multiplicity fit its electron count) are not applied to it, except that strict reading rejects a file of no atoms (lenient reading keeps it, with an :xyz_no_atoms warning). An xyz file must hold one frame: of several, strict reading throws and lenient reading takes the first, with an :xyz_frames warning. A file that is not valid UTF-8 is an InputError naming the line of the first invalid character, in both modes.

QuantumEngine.Input.input_format Function
julia
input_format(path::AbstractString) -> InputFormat

The format of the input file path, by its extension compared without regard to case: xyz, pdb and cif are the molecule files XYZ, PDB and CIF, yaml and yml are YAML_INPUT, json is JSON_INPUT, and any other extension, or none, is INP. source

parse_inp(text; source, lenient) reads an input file in the .inp format into a ParsedInput: the InputFile and the warnings of lenient reading. molecule(inp) builds the Molecule of the result.

julia
using QuantumEngine
p = parse_inp(read("h2.inp", String); source = "h2.inp")
mol = molecule(p.input)

Reading is strict by default: every input that the Rust quantum_engine (the oracle) accepts silently but that is not valid is an InputError naming the file and the line, printed as input: h2.inp:9: keywordchargegiven twice (lines 2 and 9). With lenient = true such an input is read as the oracle reads it and recorded as an InputWarning. An input that the oracle itself rejects is an error in both modes.

Lines ​

The text must be valid UTF-8: otherwise it is, in both modes and for every format parse_input reads, the file is not valid UTF-8, naming the line of the first invalid character. Each line is read in this order:

  1. A UTF-8 byte-order mark on the first line, a trailing carriage return and the surrounding whitespace are removed, so CRLF files and tab-separated tokens read as LF, space-separated ones.

  2. A line that starts with # is a comment. The first comment line, while no title is set, gives the title: the text after the #, stripped. A title keyword replaces it wherever it appears.

  3. The line is split into tokens at spaces and tabs. A token that starts with # ends the line, so charge 0 # neutral is charge 0. A line with no token is skipped.

The first token is the keyword, read without regard to case. A first token that ends in :, or a line that starts with -, is rejected as YAML: YAML input needs a .yaml or .yml extension.

Values ​

  • Counts. Each keyword takes the number of values in the table below. Another count is an error: , , . A block opener that takes no value (hubbard, cell, pbc, oniom) and gets one is .

  • Booleans are exactly true or false.

  • Integers are decimal, with an optional sign. The counts that the oracle stores unsigned (multiplicity, max_iterations, ts_target_mode, neb_images, verbosity, pcm_grid, kpoints, dos_k_grid, irc_max_points, tddft_states, dmft_n_freq, dmft_n_bath and the ONIOM model multiplicity) take no - sign: -1 is expected a non-negative integer, and in lenient reading takes the keyword's fallback below.

  • Numbers are decimal floats, finite: nan, inf and a value beyond the Float64 range (1e500) are expected a finite number, a value below it (1e-400) reads as 0.0, and a hexadecimal float is not a number.

  • Words are looked up without regard to ASCII case in the keyword's vocabulary; an unknown word is  .

  • Atom indices (freeze_*, fragments, the ONIOM model atoms) are 0-based integers in the file and 1-based in InputFile.

  • Repetition. A keyword given twice, under any of its aliases, is an error naming both lines; optimize and run, and gpu and compute_mode, count as one keyword. The freeze_* keywords repeat, each adding a constraint. A second geometry or product_geometry block is second geometry block (first at line 4).

Blocks ​

geometry [unit], product_geometry [unit], charges [unit], hubbard, fragments, cell, pbc and oniom open a block, which end closes. The unit is angstrom or ang (the default) or bohr or au, in any case, and applies to that block alone. Inside a block, a line that is a keyword or that is not the block's content is an error, ; a line whose first word is not a keyword either says so and lists the keywords, as an unknown keyword does (); and a block still open at the end of the file is .

The fragments keyword with two or more fragments on its line, fragments 0,1,2 ; 3,4,5, needs no block; with none it opens one. An empty fragment or an index that is not an integer ≥ 0 is an error.

After the file ​

  • An input without atoms is no atoms: the input has no geometry block.

  • rhf, rmp2, rccsd, rmp2-f12 and rccsd-f12 request a restricted reference, and a multiplicity other than 1 is an error at the method line.

  • The charge and multiplicity must give whole numbers of α and β electrons; the error names the multiplicity line.

  • Solvation does not depend on the order of its lines. The model is the solvation word if given; otherwise solvent gives SMD and epsilon alone gives PCM. Under PCM, epsilon, pcm_radii and pcm_grid apply; under SMD, solvent, pcm_grid and epsilon apply, and epsilon replaces the dielectric constant of the solvent (custom_epsilon == true). solvent with solvation pcm, pcm_radii under SMD, pcm_radii or pcm_grid without a model, and any solvation option with solvation none are errors.

  • f12_gamma and f12_model need f12 true or an F12 method (mp2-f12, ccsd-f12, ccsd(t)-f12 and their spellings).

Lenient reading ​

With lenient = true, each input of the tables below is read as the oracle reads it and recorded as an InputWarning whose case names it; in strict mode each is an InputError. The tables are the complete record of what lenient reading accepts. An input the oracle itself rejects (marked "error") is an error in both modes.

QuantumEngine.Input.parse_inp Function
julia
parse_inp(text::AbstractString; source = "<string>", lenient = false) -> ParsedInput

The input file text in the .inp format, read strictly by default. source names the file in error messages and warnings. Lines are keyword value…, case-insensitive in the keyword, with blocks (geometry [unit], product_geometry [unit], charges [unit], hubbard, fragments, cell, pbc, oniom) closed by end; a # starts a comment, and the first comment line gives the title unless a title keyword does. The grammar, its deviations from the oracle and every keyword are documented on the Input page of the manual.

In strict mode every input the oracle accepts silently but that is not valid is an InputError naming the line. In lenient mode (lenient = true) such an input is read as the oracle reads it and recorded as an InputWarning in the result. Text that is not valid UTF-8 is an InputError naming the line of the first invalid character, in both modes. Atom positions are converted to bohr.

QuantumEngine.Input._finalize_input Function
julia
_finalize_input(inp::InputFile; source = "<input>", lenient = false, warnings = InputWarning[], method_line = 0, multiplicity_line = 0, charge_line = 0, sites = _IndexSites()) -> InputFile

The checks every input format shares, run once after the parse of inp from source: the input has atoms; every atom index of a constraint, a fragment or the ONIOM model atoms names one of its atoms, no constraint names an atom twice and no atom is in two fragments (in lenient mode each is kept, as the oracle keeps it, with an :atom_index_range or :repeated_atom warning naming the line and label of sites); a method with a restricted reference has multiplicity 1 (in lenient mode the reference becomes AutoReference, as the oracle chooses it, with a :rhf_open_shell warning); and the charge and multiplicity give a whole number of α and β electrons. The errors name the line of method, of multiplicity and of charge (0 for a structured input or a keyword not given): a charge above the nuclear charge is reported at the charge line, the other electron-count errors at the multiplicity line; an ArgumentError of the electron counts is rethrown as an InputError with its message. Every parser passes source, lenient and warnings; the defaults give the method a call without keywords, which the type-stability check of the module judges.

Structured input (JSON, dictionaries, YAML) ​

parse_json(text; source, lenient) reads a JSON input file: json_node(text) reads the text with JSON.jl into a tree of Nodes, and parse_structured(root; source, lenient) reads the tree into a ParsedInput. Any reader that builds a Node tree reaches the same schema. A JSON integer is an integer and a number with a fraction or an exponent is a number; a number beyond the Float64 range is ±Inf. A key given twice in one object is an error in both modes, as the oracle's reader rejects it, and so is an integer outside the Int64 range; both name the key path (input: a.json: scf: duplicate key "a"). Text that is not JSON is, in both modes, not valid JSON (<JSON.jl's message>). Each of these is an InputError of line 0.

julia
using QuantumEngine
p = parse_json(read("fe2_dmft.json", String); source = "fe2_dmft.json")

Keys are case-sensitive. Messages name the key path, with 1-based list positions, and line 0: input: a.json: geometry[2].position[3]: expected a number, got a string. The checks shared with .inp (atoms given, every atom index of a constraint or of the ONIOM model atoms within the atoms and no atom twice in one constraint, a restricted reference only for a singlet, whole numbers of α and β electrons) run last, with the .inp messages.

An entry of pbc that is not a Boolean is :yaml_wrong_type and reads as true, an entry of kpath or population that is not a string is dropped (a population list with a bad entry keeps the default analyses), and a hubbard, u_map or j_map value that is not a number is dropped. The units au and ang mean bohr and Å in both modes; the oracle reads only bohr as bohr and every other unit as Å. A method word in an ONIOM map is read without regard to case, which the oracle does only for the top-level method.

Dictionaries and YAML files ​

parse_dict(d; source, lenient) reads structured input from any AbstractDict, as YAML.jl, JSON.jl and other readers build one: node(d) converts it to a Node tree and parse_structured reads the tree, so a dictionary meets the schema and the lenient cases above. Maps keep the dictionary's iteration order. Keys are converted with String; a key that is not a string, a key repeated within one map (two keys that convert to the same String), an integer outside the Int64 range and a value that is not a map, a vector, a Boolean, an integer, a floating-point number, a string, nothing or missing are errors in both modes, naming the key path: input: a.yaml: title: unsupported value of type Dates.Date. nothing and missing are null.

julia
using QuantumEngine
p = parse_dict(Dict("unit" => "bohr", "geometry" => [Dict("symbol" => "H", "position" => [0, 0, 0])],
    "multiplicity" => 2); source = "h")

parse_yaml(text; source, lenient) reads a YAML file. It has a method only once YAML.jl is loaded (using YAML loads the extension QuantumEngineYAMLExt); YAML.jl is not a dependency of the package. The extension reads the text with YAML.jl, keeping each mapping as written, in the order of the file and with any repeated key, and calls parse_dict. A key given twice in one mapping is an error in both modes, as the oracle's reader (yaml-rust2) rejects it; YAML.jl itself logs an error and keeps the last value, and its log message appears before the error. An empty document is the document is empty in both modes. A document that is not a mapping is top-level YAML document is not a mapping in strict mode, and in lenient mode, as the oracle reads a document without keys, no atoms: the input has no geometry block. Of several documents, the first is read, as the oracle reads it. Text that YAML.jl's parser or scanner rejects (an unterminated quoted string, or a tab between a keyword and its value) is, in both modes, not valid YAML (<YAML.jl's message>); YAML.jl's other errors are its own. That message and the not-a-mapping message end in ; this file looks like .inp syntax when the first line that is neither blank nor a # comment (after a byte order mark, if any) is a keyword value line (a word that starts with a letter, then whitespace and a value), as in an .inp file read as YAML. A merge key (<<) is YAML merge keys (<<) are not supported in both modes (see the table below).

YAML.jl decides the type of each scalar. Where it differs from yaml-rust2 0.9.0, which the oracle uses for .yaml, .yml and .json files, the schema's type checks decide: a value of the wrong type for its key is an error in strict mode and the lenient case of the table above in lenient mode. JSON.jl rejects each of these forms as invalid JSON: not valid JSON (<JSON.jl's message>).
